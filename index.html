Topic 1 · 9/2 – 9/16

The physical robot: frames, transforms, forward kinematics

Everything later in the course (Jacobians, IK, planning, dynamics) is built on one skill: tracking where a point is, in which frame, and chaining transforms to get there.

What a robot is: links, joints, configuration space

9/2
Big ideaA rigid robot is rigid links glued together by joints. Each free link in 3-D has 6 DOF; every joint removes some of them. Whatever freedom is left is described by the joint values $q$, and the set of all valid $q$ is the configuration space.
Core picture

The robot runs a loop: perception (sense, estimate) → control/planning → actuation (motors) → environment → back to perception. Underneath is a model $\dot x = f(x,u)$: how the state changes given inputs. Fast loop (>15 Hz): collision avoidance, tracking. Slow loop: planning, estimating.

Joints remove DOF

DOF the joint allows + constraints it imposes = 6 in space (3 in plane).

  • Serial (open chain): no loops. Arms, SCARA. Parallel (closed chain): loops. Delta, Stewart platform.
  • Robots are named by joint strings, e.g. RRP = revolute, revolute, prismatic (SCARA-like). Underline = actuated.
  • Configuration $q$ = a kinematically feasible arrangement of links/joints. C-space = all of them. Inputs change configuration: $\dot q = f(q,u)$.
  • Workspace = where the end effector works (usually $\mathbb R^2$ or $\mathbb R^3$). End effector = the part of the chain the task cares about.
Redundancy vs actuation (two different questions)
  • Redundancy compares inputs to end-effector DOF. Redundant: # inputs > workspace DOF (7-joint Panda reaching a 6-DOF pose), so many $q$ give the same pose. Hyper-redundant: snake robots.
  • Actuation asks whether every state can be pushed directly. Under-actuated: some states only change indirectly.
Example: under-actuationA point mass: $\dot q = \begin{bmatrix}\dot x\\ \dot v\end{bmatrix} = \begin{bmatrix} v \\ F/m\end{bmatrix}$. The force $F$ only touches $\dot v$; position changes only through velocity. A quadrotor is the classic robot case: 4 thrusts all point up, so to move sideways it must first tilt.
A 7-joint arm controls a 6-DOF end-effector pose. Redundant, under-actuated, or both?
Redundant (7 inputs > 6 task DOF, so a self-motion exists, like moving the elbow while the hand stays still). Not under-actuated: each joint has its own motor.
How many DOF does a spherical joint leave between two spatial bodies?
3 (all rotations), so it imposes 6 − 3 = 3 constraints (the translations).

Frames, coordinates, rotation matrices

9/9
Big ideaA point is a physical thing; its coordinates depend on which frame you measure from. A rotation matrix's columns are literally the other frame's axes, written in your frame.
Notation (Tron's convention)

${}^B x$ = coordinates of point $x$ expressed in frame $B$. A frame = orthonormal right-handed axes + an origin. ${}^W R_B, {}^W p_B$ = pose of $B$ seen from $W$. Read subscripts like units: the inner indices must match and cancel.

$${}^W x = {}^W R_B\,{}^B x + {}^W p_B$$
rigid body transformation: rotate B-coordinates into W's axes, then shift by where B's origin is
  • Plug in ${}^B x = 0$ (B's own origin) → ${}^W x = {}^W p_B$. So $p$ is "where B's origin is, in W."
  • Plug in ${}^B x = e_1$ → ${}^W x = r_1$, the first column of $R$. So column $i$ of ${}^W R_B$ = B's $i$-th axis expressed in W.
  • Point − point = vector, point + vector = point, point + point = undefined. Vectors (displacements) ignore translation.
$$R_z(q) = \begin{bmatrix}\cos q & -\sin q & 0\\ \sin q & \cos q & 0\\ 0&0&1\end{bmatrix},\quad R_x(q) = \begin{bmatrix}1&0&0\\0&\cos q&-\sin q\\0&\sin q&\cos q\end{bmatrix},\quad R_y(q)=\begin{bmatrix}\cos q&0&\sin q\\0&1&0\\-\sin q&0&\cos q\end{bmatrix}$$
elementary rotations; the 2-D rotation is the top-left block of R_z. Note R_y's sign flip (z × x = y ordering)
Why $R^{-1} = R^T$

$R^TR$ is a table of dot products $\langle r_i, r_j\rangle$. The columns are orthonormal axes, so that table is $I$. Right-handed frames add $\det R = 1$. Together: $SO(3) = \{R\in\mathbb R^{3\times3}: R^TR = I,\ \det R = 1\}$.

Worked example (activity 9/8)B sits at $(3,1)$ rotated 45°. Point $x_A$ is the tip of B's first axis, so ${}^B x_A = [1, 0]^T$. B's first axis in W is $r_1 = [\cos 45°, \sin 45°]^T = [\tfrac{1}{\sqrt2}, \tfrac{1}{\sqrt2}]^T$, so $${}^W x_A = {}^W R_B \begin{bmatrix}1\\0\end{bmatrix} + \begin{bmatrix}3\\1\end{bmatrix} = \begin{bmatrix}3+\tfrac{1}{\sqrt2}\\ 1+\tfrac{1}{\sqrt2}\end{bmatrix}.$$ Same idea for $x_B$ (tip of B's second axis): ${}^B x_B = [0,1]^T$, ${}^W x_B = [3 - \tfrac{1}{\sqrt2},\ 1+\tfrac{1}{\sqrt2}]^T$.
Trap: ${}^W R_B\,{}^W x$ is meaningless (Tron crossed it out in red). ${}^W R_B$ only eats B-coordinates. Check the indices every time.
A robot reports ${}^W p_B = [2,0,0]^T$ and ${}^W R_B = R_z(90°)$. Where in W is the point ${}^B x = [1,0,0]^T$?
$R_z(90°)$'s first column is $[0,1,0]^T$ (B's x-axis points along W's y). So ${}^W x = [0,1,0]^T + [2,0,0]^T = [2,1,0]^T$.
Why must $\det R = +1$ and not just $\pm 1$?
$R^TR = I$ alone allows reflections ($\det = -1$), which turn a right-handed frame into a left-handed one. No physical motion does that.

Composition, homogeneous transforms, forward kinematics

9/14
Big ideaForward kinematics is just "chain the frames." Pack $(R,p)$ into one 4×4 matrix $T$ and the chain becomes plain matrix multiplication where inner indices cancel: ${}^0T_1\,{}^1T_2\,{}^2T_E = {}^0T_E$.
Composition by substitution

Substitute ${}^1x = {}^1R_2\,{}^2x + {}^1p_2$ into ${}^0x = {}^0R_1\,{}^1x + {}^0p_1$:

$${}^0R_2 = {}^0R_1\,{}^1R_2,\qquad {}^0p_2 = {}^0R_1\,{}^1p_2 + {}^0p_1$$
rotations multiply; translations add after rotating ¹p₂ into frame 0's axes
Homogeneous coordinates

Append a 1 to points, a 0 to vectors. Then one matrix does rotation and translation together, and vectors automatically ignore translation (the 0 kills the $p$ column).

$${}^W T_B = \begin{bmatrix}{}^W R_B & {}^W p_B\\ 0^T & 1\end{bmatrix},\qquad \begin{bmatrix}{}^W x\\1\end{bmatrix} = {}^W T_B \begin{bmatrix}{}^B x\\1\end{bmatrix}$$
SE(3) = all such matrices with R ∈ SO(3), p ∈ ℝ³
$${}^B T_W = ({}^W T_B)^{-1} = \begin{bmatrix}{}^W R_B^T & -{}^W R_B^T\,{}^W p_B\\ 0^T & 1\end{bmatrix}$$
inversion: swap the indices. The translation is NOT just −p; it must be rotated into B's axes
Worked example: the spherical robot (activity 9/8, solved 9/14)Base link (red) along z, joint $q_1$ about z, link (green) along z, joint $q_2$ about local x, link (blue) along y to the end effector. Read right to left, peeling one frame at a time: $${}^0T_E = \underbrace{\begin{bmatrix}R_z(q_1) & p_z(\ell_{red})\\0&1\end{bmatrix}}_{0\leftarrow1}\underbrace{\begin{bmatrix}R_x(q_2) & p_z(\ell_{green})\\0&1\end{bmatrix}}_{1\leftarrow2}\underbrace{\begin{bmatrix}I & p_y(\ell_{blue})\\0&1\end{bmatrix}}_{2\leftarrow E}$$ Multiplying the blocks out gives exactly the substitution answer: ${}^0p_E = R_z(q_1)R_x(q_2)\,p_y(\ell_{blue}) + R_z(q_1)\,p_z(\ell_{green}) + p_z(\ell_{red})$ and $R = R_z(q_1)R_x(q_2)$.
Trap: order matters. $R_z(q_1)R_x(q_2) \ne R_x(q_2)R_z(q_1)$. The factor closest to the base goes on the left.
Trap: in ${}^0p_2 = {}^0R_1\,{}^1p_2 + {}^0p_1$, forgetting to rotate ${}^1p_2$ is the most common mistake. ${}^1p_2$ is written in frame 1's axes; you can't add it to a frame-0 vector until it's rotated.
Why does a vector get a 0 in the 4th slot instead of a 1?
A vector is a displacement (difference of two points: $[\ast,1] - [\ast,1] = [\ast,0]$). Moving the frame's origin doesn't change a displacement, and the 0 makes $T$ skip the translation column.
Which is correct: ${}^W x = {}^B R_W\,{}^B x + {}^B p_W$ or ${}^W x = {}^W R_B\,{}^B x + {}^W p_B$?
The second (the 9/14 quiz). Indices: ${}^W R_B\,{}^B x$, the B's cancel and the result is in W. The first has mismatched frames.

URDF, spatialmath, Robotics Toolbox, Swift

9/14 – 9/16
Big ideaA URDF is the forward-kinematics chain written as XML. Each joint's <origin> is a fixed transform from parent to child, and its <axis> says which elementary motion $q$ drives. FK = product of (fixed origin) × (joint motion) down the chain.
URDF anatomy
  • <robot name> is the top tag. URDF only supports open chains (MuJoCo supports closed; USD is the newer NVIDIA format; XACRO = URDF + macros).
  • <link> has <visual> (rendering), <collision> (collision shape), <inertial> (mass, COM origin, inertia ixx ixy ixz iyy iyz izz: 6 numbers because the tensor is symmetric).
  • <joint type>: revolute (with limits), continuous (revolute, no limits), prismatic (translation), fixed. Has <parent link>, <child link>, <origin xyz rpy> in the parent frame, <axis xyz>, <limit>. Links are referenced by name.
$${}^0T_E(q) = \prod_i \underbrace{T_{origin,i}}_{\text{fixed, from }\langle origin\rangle}\;\underbrace{T_{joint,i}(q_i)}_{R_{axis}(q_i)\text{ or }p_{axis}(q_i)}$$

<origin xyz rpy> inside the joint, expressed in the parent link's frame.

Derivatives of poses: angular velocity, twists, Lie derivatives

9/16
Big ideaDifferentiate a rotation matrix and you always get $R$ times a skew-symmetric matrix. That skew matrix is just the angular velocity vector $\omega$ in disguise (the "hat" of $\omega$).
Worked: derivative of a 2-D rotation $$\frac{d}{dt}\begin{bmatrix}\cos q & -\sin q\\ \sin q&\cos q\end{bmatrix} = \begin{bmatrix}-\dot q\sin q & -\dot q\cos q\\ \dot q\cos q&-\dot q\sin q\end{bmatrix} = R(q)\underbrace{\begin{bmatrix}0&-\dot q\\ \dot q&0\end{bmatrix}}_{\hat\omega}$$ The angular velocity is $\dot q$, packed into a skew-symmetric matrix.
$${}^W\dot R_B = {}^W R_B\,\hat\omega,\qquad \hat\omega = \begin{bmatrix}0&-\omega_3&\omega_2\\ \omega_3&0&-\omega_1\\ -\omega_2&\omega_1&0\end{bmatrix},\qquad \hat\omega\, v = \omega\times v$$
ω̂ on the right of R → ω in body coordinates. ω̂ on the left (Ṙ = ω̂R) → ω in world coordinates
Heads up: the 3×3 skew matrix in the 9/16 notes is written with the opposite signs. Use the version above: it matches the 2-D case, matches $\hat\omega v = \omega\times v$, matches spatialmath's skew(), and is the one Tron wrote in the 10/26 warm-up poll.
  • Skew-symmetric: $A = -A^T$, so the diagonal is zero. 2×2 has 1 free number, 3×3 has 3. Hat $\wedge$: vector → matrix. Vee $\vee$: matrix → vector.
  • Derivative of a curve $f(t)$ = tangent = velocity. Derivative of ${}^Wp_B(t)$ = linear velocity of the body in W.
  • Twist = (angular velocity, linear velocity) together; it's the derivative of a pose: $\frac{d}{dt}T = \begin{bmatrix}R\hat\omega & \dot p\\ 0 & 0\end{bmatrix}$.
Lie derivative
$$\mathcal L_{\dot x} F = \frac{d}{dt}F(x(t))$$
rate of change of a field F as you move along a curve x(t). This is the workhorse for every derivative in topic 2

Picture a hiker on a hill: $F$ is altitude, $x(t)$ is the trail, and the Lie derivative is how fast the hiker's altitude changes. It depends on both the terrain and which way (and how fast) they're walking.

Why is $\dot R R^T$ always skew-symmetric? (Hint: differentiate $RR^T = I$.)
$\frac{d}{dt}(RR^T) = \dot RR^T + R\dot R^T = 0$, so $\dot RR^T = -(\dot RR^T)^T$. That's the definition of skew-symmetric.
Topic 2 · 9/21 – 10/7

Derivative works: Jacobians, gradient descent, least squares, constraints

One definition does almost all the work here: the gradient is whatever vector makes $\frac{d}{dt}f(x(t)) = \langle \mathrm{grad} f, \dot x\rangle$. Every derivation in this topic (Jacobians, least squares, IK) is that definition applied carefully.

Lie derivatives, gradients, Jacobians

9/21
Big ideaMove along a curve and ask "how fast does $F$ change?" The answer is always (something that depends on where you are) × (how fast you're moving). For scalar $F$ that something is the gradient; for vector $F$ it's the Jacobian matrix.
$$\frac{d}{dt}F(x(t)) = \mathcal L_{\dot x}F = \langle \mathrm{grad}\,F(x),\ \dot x\rangle \qquad\text{(scalar }F\text{)}$$ $$\underbrace{\frac{d}{dt}F(x(t))}_{\mathbb R^m} = \underbrace{J_F(x)}_{m\times n}\ \underbrace{\dot x}_{\mathbb R^n},\qquad J_{ij} = \frac{\partial F_i}{\partial x_j}\qquad\text{(vector }F\text{)}$$
definition of gradient and Jacobian, both read off from the Lie derivative
  • Gradient = direction of steepest ascent: among unit $\dot x$, $\langle \mathrm{grad}F,\dot x\rangle$ is biggest when $\dot x$ points along grad F.
  • In coordinates, grad F = column of partials. Each partial is a Lie derivative along a basis direction: $\partial F/\partial x_i = \mathcal L_{E_i}F$.
  • Gradient is orthogonal to level sets: walking along a level set, $F$ doesn't change, so $\langle\mathrm{grad}F,\dot x\rangle = 0$.
  • For a robot, $F$ = forward kinematics, $x = q$: ${}^0\dot p_E = J(q)\,\dot q$. Column $i$ of $J$ = end-effector velocity when only joint $i$ moves at unit speed ($Je_i = j_i$).
Worked: Jacobian of the spherical robot by hand (activity 9/21) With $\ell_{red}=\ell_{green}=0$, $\ell_{blue}=0.8$: ${}^0p_E = R_z(q_0)R_x(q_1)\begin{bmatrix}0\\0\\0.8\end{bmatrix} = \begin{bmatrix}0.8\sin q_0 \sin q_1\\ -0.8\cos q_0\sin q_1\\ 0.8\cos q_1\end{bmatrix}$.
Product rule (order matters with matrices), using $\dot R_z = R_z\,[0,0,\dot q_0]^\wedge$ and $\dot R_x = R_x\,[\dot q_1,0,0]^\wedge$: $$\dot p = \underbrace{R_z\,\hat e_3\,R_x\,p_{blue}}_{j_1}\,\dot q_0 + \underbrace{R_zR_x\,\hat e_1\,p_{blue}}_{j_2}\,\dot q_1,\qquad J = \begin{bmatrix}0.8\sin q_1\cos q_0 & 0.8\sin q_0\cos q_1\\ 0.8\sin q_0\sin q_1 & -0.8\cos q_0\cos q_1\\ 0 & -0.8\sin q_1\end{bmatrix}$$ Sanity check: column 1 has zero z-component. Spinning about the vertical axis never moves the tip up or down. ✓

Tron's key line: "It should always be possible to write the Lie derivative as a matrix that depends on q times the vector of qdot." If you can't factor out $\dot q$, you've made an algebra mistake.

$F:\mathbb R^3\to\mathbb R^2$. What size is $J_F$, and what does row 2 mean?
$2\times3$. Row 2 is the gradient of $F_2$ (transposed): how the second output responds to each input.
Why is $\langle \mathrm{grad}f, \dot x\rangle$ maximized when $\dot x \parallel \mathrm{grad}f$?
$\langle v,w\rangle = \|v\|\|w\|\cos\theta$. With $\|w\|=1$ fixed, it's largest at $\theta=0$.

Jacobians in code, the 6-row Jacobian, rotation representations

9/23
Big ideaThere are three ways to get the same $J$: differentiate the FK symbolically, push unit joint velocities through the product-rule formula one column at a time, or call jacob0(). The built-in one has 3 extra rows: the angular velocity part.
q = sp.symbols(['q0', 'q1'])
f = sp.Matrix(robot_fkine_ee(q))       # RTB gives numpy arrays of sympy exprs; convert first
J1 = f.jacobian(q)                      # 1) symbolic
J2 = [robot_fkine_ee_jacob(q, [1,0]),   # 2) J e_i = column i
      robot_fkine_ee_jacob(q, [0,1])]
J3 = sp.simplify(robot.jacob0(q))       # 3) built-in, 6 x n
# skewa([vx,vy,vz,wx,wy,wz]) = 4x4 hat; spatialmath orders (v, omega)
$$\begin{bmatrix}\dot p\\ \omega\end{bmatrix} = \underbrace{\begin{bmatrix}J_p\\ J_\omega\end{bmatrix}}_{\texttt{jacob0}:\ 6\times n}\dot q,\qquad J_\omega = \begin{bmatrix}0 & \cos q_0\\ 0&\sin q_0\\ 1&0\end{bmatrix}\ \text{(spherical robot)}$$
top 3 rows: linear velocity. bottom 3: angular velocity (from Ṙ = Rω̂, then vee). HW2 uses only Jp = jacob0(q)[:3,:]

Read $J_\omega$ physically: joint $q_0$ always spins about world z ($[0,0,1]$). Joint $q_1$ spins about its local x-axis, which has been rotated by $q_0$, so in world coordinates it's $[\cos q_0, \sin q_0, 0]$.

Composition rule worth memorizing
$$\begin{bmatrix}R_1&p_1\\0&1\end{bmatrix}\begin{bmatrix}R_2&p_2\\0&1\end{bmatrix} = \begin{bmatrix}R_1R_2 & R_1p_2+p_1\\0&1\end{bmatrix}$$
rotations affect rotations and translations; translations never affect rotations

What do the extra three rows of jacob0() mean? (activity Q1.3)
They map $\dot q$ to the end effector's angular velocity $\omega$ (in the base frame). Top 3 rows map $\dot q$ to linear velocity.
Why do we wrap the RTB output in sp.Matrix(...)?
RTB returns a NumPy array whose cells are SymPy expressions. NumPy arrays don't have .jacobian(); SymPy matrices do.

Unconstrained optimization and gradient descent

9/28
Big ideaAt a minimum, no direction goes downhill, so grad f = 0. Gradient descent finds such points by repeatedly stepping downhill. It's guaranteed to go down, but only to the nearest valley.
  • Critical points: grad f = 0. Could be a min, max, or saddle. Minima can be local or global, and may not be unique (symmetry gives whole lines of minimizers).
  • Scaling or shifting doesn't move the minimizer: $\arg\min f = \arg\min (af + c)$ for $a>0$. That's why we use $\tfrac12\|\cdot\|^2$: the ½ cancels the 2 from differentiation.
$$\underbrace{\dot x = -\mathrm{grad}\,f(x)}_{\text{gradient flow (continuous)}}\quad\xrightarrow{\ \text{forward Euler}\ }\quad \underbrace{x[k+1] = x[k] - \varepsilon\,\mathrm{grad}\,f(x[k])}_{\text{gradient descent}}$$
repeat until ‖grad f‖ < tolerance. ε = step size

Why it always goes down: plug the flow into the Lie derivative: $\frac{d}{dt}f = \langle \mathrm{grad}f, -\mathrm{grad}f\rangle = -\|\mathrm{grad}f\|^2 \le 0$. Zero only at critical points (the equilibria of the flow).

Limitations
  • Multiple local minima → answer depends on the initial guess. Fixes: convex problems, warm starts, convex approximations.
  • Can stall at a saddle or a max if you start exactly there.
  • Step size: too small = slow, too big = overshoot/unstable.
  • Conditioning: round level sets → gradient points straight at the minimum. Long skinny ellipses → gradient points across the valley, so GD zig-zags.
Example: step size on $f(x) = \tfrac12 x^2$grad f = x, so $x[k+1] = (1-\varepsilon)x[k]$. $\varepsilon = 0.5$: halves each step (converges). $\varepsilon = 1$: lands on 0 in one step. $\varepsilon = 2.5$: multiplies by −1.5 each step (diverges, flipping sign). Stable iff $0 < \varepsilon < 2$.

Topology (side note in the 9/28 notes): a topology says which points are "close" without needing distance. A neighborhood of $x$ is an open set containing it. Gluing the ends of an interval makes a circle, which is why joint angles live on a circle, not a line.

Gradient flow converges to a critical point. Why "in general a local minimum"?
Maxima and saddles are unstable equilibria: any tiny perturbation pushes you off downhill. Only minima attract nearby trajectories.

Linear least squares

9/30
Big ideaToo many equations, no exact solution? Pick the $x$ that makes the leftover errors (residuals) as small as possible in total squared size. Because the cost is a quadratic bowl, setting the gradient to zero gives a closed-form answer.
  • Measurements $a_i^Tx = b_i$ stacked into $Ax \approx b$. Underdetermined ($N < \dim x$): infinitely many solutions. Determined: one. Overdetermined: usually none exact.
  • Residuals $r = Ax - b$. Problem: $\min_x \|Ax-b\|^2$.
Derivation (activity 9/30, exactly how Tron does it)

$f = \tfrac12(Ax-b)^T(Ax-b) = \tfrac12[x^TA^TAx - 2b^TAx + b^Tb]$ (using: a scalar equals its transpose, so $x^TA^Tb = b^TAx$). Differentiate along $x(t)$:

$$\frac{d}{dt}f = \tfrac12[\dot x^TA^TAx + x^TA^TA\dot x] - b^TA\dot x = (A^TAx - A^Tb)^T\dot x = \langle \underbrace{A^TAx - A^Tb}_{\mathrm{grad} f},\ \dot x\rangle$$ $$\mathrm{grad}f = 0\ \Rightarrow\ A^TAx^* = A^Tb\ \Rightarrow\ \boxed{x^* = (A^TA)^{-1}A^Tb}$$
normal equations. needs A^T A invertible (A has full column rank)
Worked: fit a line $y = c_0 + c_1 t$ to (0,1), (1,2), (2,2) $A = \begin{bmatrix}1&0\\1&1\\1&2\end{bmatrix}$, $b = \begin{bmatrix}1\\2\\2\end{bmatrix}$, $A^TA = \begin{bmatrix}3&3\\3&5\end{bmatrix}$, $A^Tb = \begin{bmatrix}5\\6\end{bmatrix}$ → $x^* = \begin{bmatrix}7/6\\ 1/2\end{bmatrix}$. Residuals $[\tfrac16, -\tfrac13, \tfrac16]$: no line hits all three, this one balances the misses.
The activity's CVXPY problem ($A$ = 3×3, $b = [4,1,2]$) is square and invertible, so the answer is exact: $x^* = [1, 2, 3]^T$, cost 0.

Used later for estimation (localization) and planning (spline fitting in topic 3).

Why can we drop the ½ or add constants to the cost without changing $x^*$?
Positive scaling and shifting don't change where the minimum is, only its height.
Geometrically, what's special about the residual $Ax^*-b$ at the optimum?
$A^T(Ax^*-b) = 0$: the residual is orthogonal to every column of $A$. $Ax^*$ is the projection of $b$ onto the column space.

Inverse kinematics by gradient descent

9/30 · HW2
Big ideaIK = "find joints that put the hand at $p^*$." Write it as nonlinear least squares, $\min_q \tfrac12\|F(q)-p^*\|^2$. The gradient is just $J^T$ times the position error, so each GD step converts "hand is off by this much" into "nudge joints by this much."
$$\mathrm{grad}_q f = J(q)^T\big(F(q) - p^*\big),\qquad q[k+1] = q[k] - \varepsilon\,J^T\big(F(q[k]) - p^*\big)$$
derived by chaining least squares (A = I, x = F(q)) with ẋ = J q̇

Derivation in one line: $\frac{d}{dt}f = (F(q)-p^*)^T\dot x = (F(q)-p^*)^TJ\dot q = \langle J^T(F(q)-p^*),\ \dot q\rangle$.

  • Works for unreachable targets: it just gets as close as possible (that's the least-squares advantage).
  • Multiple solutions: elbow-up vs elbow-down. Which one you get depends on $q_0$ (HW2 Report 1.4).
  • Nullspace: $N(J) = \{v: Jv = 0\}$ = joint motions that don't move the hand. "Fat" Jacobians (redundant robots like Panda, 3×7 for position) always have one. Adding a nullspace term lets you pursue a secondary goal (avoid obstacles, stay away from limits) for free.
  • Joint limits (HW2): clamp $q$ to its limits after each step. That's projected gradient descent onto a box (next sections).
Trap: it's $J^T$, not $J^{-1}$. $J$ is often non-square or singular; $J^T$ always exists and always gives a descent direction.
At a singularity (arm fully straight), what happens to GD-IK for a target straight out along the arm?
Both Jacobian columns are perpendicular to the arm, so $J^T e = 0$ for an error along the arm. The gradient vanishes even though the error doesn't: GD stalls. (It's also unreachable if it's beyond $l_1+l_2$.)
Panda IK for position: what's the size of $J_p$, and does it have a nullspace?
3×7. Fat, so its nullspace is at least 4-dimensional: many joint motions keep the hand still.

Convexity and CVXPY

9/30 – 10/5
Big ideaConvex = bowl-shaped with no false valleys, so every local minimum is the global one and gradient descent can't get stuck. CVXPY only lets you build problems out of pieces whose convexity it can certify, which is why its answers are always global.
  • Convex set: the segment between any two points stays inside. $\lambda x_2 + (1-\lambda)x_1 \in S$ for $\lambda\in[0,1]$. Rings, U-shapes, letters with holes: not convex.
  • Convex function: chord lies above the graph: $f(\lambda x_2+(1-\lambda)x_1) \le \lambda f(x_2)+(1-\lambda)f(x_1)$. Concave = $-f$ convex. Affine = both. $\sin$, $x^3$ = neither.
Rules that preserve convexity (disciplined convex programming)
  • sum of convex is convex; max of convex is convex
  • convex ∘ affine is convex: $f(Ax+b)$
  • increasing convex ∘ convex is convex: $a(f(x))$
  • product of convex is not necessarily convex
Chain it: why least squares is convex$x_i^2$ convex → $(a_i^Tx - b_i)^2$ (affine inside) → $\sum_i(\cdot)$ (sum) → $\|Ax-b\|^2$. Every step uses one rule.
x = cp.Variable((3, 1))
cost = cp.sum_squares(A @ x - b)
prob = cp.Problem(cp.Minimize(cost), constraints)   # minimize convex / maximize concave only
prob.solve()
prob.status   # 'optimal' | 'unbounded' (min is -inf) | 'infeasible' | 'inaccurate' (rescale)
x.value
Is $\max\{x^2, 2x+1\}$ convex? Is $x^2\cdot e^{x}$ guaranteed convex by the rules?
Yes (max of convex). The product isn't covered by any rule, so CVXPY would reject it even though you'd have to check by hand.

Constrained optimization, projected GD, problem classes

10/5
Big ideaOnce there's a feasible set, the best point is often on its boundary, where the gradient is not zero; it's pushing against a wall. To stay globally solvable, both the cost and the feasible set must be convex.
$$\min_x f(x)\ \ \text{s.t.}\ \ g_i(x) \le 0\ (\text{convex}),\quad h_i(x) \ge 0\ (\text{concave}),\quad a^Tx + b = 0\ (\text{affine})$$
these forms keep the feasible set convex. a nonlinear equality (e.g. a circle) is never convex. empty set → infeasible
Projected gradient descent
  1. Step: $x' = x[k] - \varepsilon\,\mathrm{grad}f(x[k])$
  2. Project: $x[k+1] = \mathrm{Proj}_S(x') = \arg\min_{x\in S}\|x - x'\|^2$

For box constraints the projection is just clamping each coordinate (HW2 joint limits). Otherwise the projection is itself an optimization. Behavior: follow the gradient from the interior until a constraint becomes active, then slide along the boundary.

A linear or bowl cost on a U-shaped region can have two separate boundary points that are each best locally. GD finds whichever is nearer.

Lagrange multipliers: why constrained minima aren't flat

10/7
Big ideaAt a constrained minimum, the cost still wants to go downhill, but every downhill direction is blocked by an active constraint. The gradient's pull is exactly balanced by the constraints' push.
$$\nabla f(x^*) = -\lambda_1\nabla g_1(x^*) - \lambda_2\nabla g_2(x^*) - \cdots,\qquad \lambda_i \ge 0\qquad\Longleftrightarrow\qquad \nabla f + \lambda^T J_g = 0$$
for min f s.t. g_i(x) ≤ 0. J_g stacks the constraint gradients as rows
  • Active constraint ($g_i(x^*) = 0$, you're on the wall): $\lambda_i > 0$.
  • Inactive ($g_i(x^*) < 0$, wall is far away): $\lambda_i = 0$; it exerts no push.
Heads up: the 10/7 notes say "lambda<0 for inactive constraints." The standard condition is $\lambda = 0$ for inactive constraints (complementary slackness: $\lambda_i g_i(x^*) = 0$), and all $\lambda_i \ge 0$.
Worked: the 10/7 activity$f = \tfrac12\|x - [1,1]^T\|^2$, constraints $g_1 = x_2 \le 0$, $g_2 = -x_1 \le 0$. Constrained min at $x^* = (1,0)$.
$\nabla f(x^*) = x^* - [1,1]^T = [0,-1]^T$ (points down, into the floor). $\nabla g_1 = [0,1]^T$ (points up, out of the feasible set). $g_2$ is inactive ($x_1 = 1 > 0$), so $\lambda_2 = 0$.
Balance: $[0,-1]^T = -\lambda_1[0,1]^T$ → $\lambda_1 = 1 > 0$. ✓ Active constraint, positive multiplier.

Gradient values worth recognizing from the same activity: $\nabla f(0,0) = [-1,-1]$, $\nabla f(-1,0) = [-2,-1]$, $\nabla f(0,2) = [-1,1]$. All point away from $(1,1)$, perpendicular to the circular level sets.

Reading $Cx \le d$

Each row $c_i^Tx \le d_i$ is a half-space: $c_i$ is the normal of the boundary line/plane, $d_i$ shifts it from the origin, and $\le$ picks the side. Stack several and you get a polytope. QP = quadratic cost + these. QCQP = quadratic constraints too (disk-shaped feasible sets).

A QP has unique solution: true in general? (10/14 poll)
No. A QP is convex with no local minima, but the minimizer can be non-unique (e.g. a flat direction in the cost).
Can you add an arbitrary constant to a QP's constraints like you can to its cost?
No. Adding a constant to the cost doesn't move the minimizer. Adding one to a constraint changes $d$, which slides the hyperplane and changes which $x$ are feasible.
Topic 3 · 10/7 – 10/21

Finding the good way: graph search, splines, sampling-based planners

Three families, one problem: get from start to goal through the free configuration space. Graph search is complete but jagged, splines are smooth but need convex regions, sampling scales to high dimensions but struggles with narrow gaps.

Free configuration space, graph search, decomposition

10/7 · 10/13
Big ideaPlan in joint space, not in the workspace. A configuration is "free" if, after forward kinematics, the robot doesn't hit anything. Discretize that free space into a graph, then any graph search finds a path.
  • Configuration space: minimal generalized coordinates (e.g. $[q_1,q_2,q_3]\in[0,2\pi)^3$). Workspace: where the robot lives ($\mathbb R^3$). FK maps the first to the second.
  • Free C-space: configurations whose FK doesn't intersect obstacles. A box in the workspace becomes a weird blob in C-space.
  • Path planning problem: a sequence of configurations in free C-space from start to goal.
Graph-based planning

Nodes = samples in free C-space (e.g. a grid), edges = feasible short motions between neighbors. Then search:

  • BFS: expands like a wavefront in all directions. DFS: runs deep down one branch. Both may search lots of space far from the goal.
  • A*: adds a heuristic (estimate of remaining distance to goal, e.g. straight-line distance) so it expands toward the goal first.
  • + Complete: returns a path if one exists in the graph, says so if not. − Approximate (only uses grid points), and paths are straight segments with velocity jumps → smooth afterwards with splines.
Decomposition-based planning

Instead of points, cover free space with convex regions (polytopes, $C_ix + d_i \le 0$). Search the graph of overlapping regions for a high-level route, then fit a curve inside the chain of regions. Trapezoidal decomposition (vertical lines from each polygon vertex) is the classic special case with straight segments. IRIS automates finding big convex regions but can be slow.

Why is a graph-based planner "complete" but only "resolution complete" in practice?
It's exact for the graph you built. If the grid is too coarse to fit through a gap, it will truthfully report "no path" even though a continuous path exists.

Function spaces and Bernstein splines

10/13 · 10/14
Big ideaTreat curves as vectors: pick basis functions, and a curve is just a set of coefficients. With the Bernstein basis, those coefficients are control points, and the curve never leaves the convex hull of its control points. Keep the control points inside a convex region and the whole curve is safe.
  • Functional vector space: "vectors" are functions; add and scale pointwise. Bases: Fourier (sines/cosines), polynomials $1, t, t^2,\dots$. Functions are infinite-dimensional, so a finite basis can't represent everything.
$$B_0 = (1-t)^3,\quad B_1 = 3t(1-t)^2,\quad B_2 = 3t^2(1-t),\quad B_3 = t^3,\qquad \sum_k B_k(t) = 1$$ $$p(t) = c_0B_0(t) + c_1B_1(t) + c_2B_2(t) + c_3B_3(t),\quad t\in[0,1]$$
cubic Bernstein basis in the order used on 10/14 and in the activity. general: b_{m,ν} = (m choose ν) t^ν (1−t)^{m−ν}
Trap: the 10/13 notes list the basis in reverse order ($t^3$ first). From 10/14 on, $B_0 = (1-t)^3$ so that $p(0) = c_0$, $p(1) = c_3$. Use the 10/14 order.
Endpoint facts (derive once, use forever)
$$\dot p(t) = 3(c_1-c_0)(1-t)^2 + 6(c_2-c_1)t(1-t) + 3(c_3-c_2)t^2$$ $$p(0)=c_0,\quad p(1)=c_3,\quad \dot p(0) = 3(c_1-c_0),\quad \dot p(1) = 3(c_3 - c_2)$$
the curve starts at c₀ heading toward c₁, ends at c₃ arriving from c₂. derivative of a cubic Bernstein curve = quadratic Bernstein curve on the differences
Why the convex hull property holds

Each $B_k(t) \ge 0$ on $[0,1]$ and they sum to 1, so $p(t)$ is a weighted average of the control points at every $t$. Weighted averages of points in a convex set stay in it.

If all four control points are inside a convex region, is the curve guaranteed inside? What if the region is L-shaped?
Convex region: yes (convex hull property). L-shaped: no, the hull of the control points can cut the corner. That's why you use one segment per convex region.
Where does a cubic Bernstein curve point at $t = 0$?
Along $c_1 - c_0$, with speed $3\|c_1 - c_0\|$. Setting $c_1 = c_0$ gives zero initial velocity.

Minimum-acceleration splines as a QP in CVXPY

10/14 · 10/15
Big ideaAmong all feasible splines, pick the one with the smallest total squared acceleration, $\int_0^1\|\ddot p\|^2dt$. That cost is quadratic in the control points and the constraints are linear, so it's a QP. Intuitively it wants velocity as constant as possible: straight, smooth, no lurching.
Derivation (activity 10/14 scan part)
$$\ddot p(t) = 6\big[\underbrace{(c_2 - 2c_1 + c_0)}_{a}(1-t) + \underbrace{(c_3 - 2c_2 + c_1)}_{b}\,t\big]$$ $$\|\ddot p\|^2 = 36\big[\|a\|^2(1-t)^2 + 2a^Tb\,t(1-t) + \|b\|^2t^2\big]$$ $$\int_0^1\|\ddot p\|^2dt = 36\Big(\tfrac13\|a\|^2 + \tfrac16\cdot 2a^Tb + \tfrac13\|b\|^2\Big) = 12\big(\|a\|^2 + a^Tb + \|b\|^2\big)$$
uses ∫(1−t)² = ∫t² = 1/3 and ∫t(1−t) = 1/6 over [0,1]. a, b are "second differences" of control points
Making CVXPY accept it

$a^Tb$ is a product of two variables, which breaks the DCP rules even though the total is convex. Complete the square:

$$\|a\|^2 + a^Tb + \|b\|^2 = \tfrac12\|a+b\|^2 + \tfrac12\|a\|^2 + \tfrac12\|b\|^2$$
check: ½(‖a‖² + 2aᵀb + ‖b‖²) + ½‖a‖² + ½‖b‖² ✓
def acceleration_cost(C):
    a = C[2] - 2*C[1] + C[0]
    b = C[3] - 2*C[2] + C[1]
    return 12*(0.5*cp.sum_squares(a + b) + 0.5*cp.sum_squares(a) + 0.5*cp.sum_squares(b))

C_A, C_B = cp.Variable((4, 2)), cp.Variable((4, 2))
prob = cp.Problem(cp.Minimize(acceleration_cost(C_A) + acceleration_cost(C_B)), constraints)
prob.solve()        # == is a constraint, not assignment; "== 0" broadcasts to a vector
Interpolating vs smoothing splines

Interpolating (planning): pass through waypoints, so data are hard equality constraints. Smoothing (filtering): data go into the cost as $\|p(t_i) - p_i\|^2$, traded against smoothness. Other regularizers: min length, min velocity, min time with velocity/acceleration limits.

Why is $\int\|\ddot p\|^2$ smallest for a straight constant-speed line?
Then $\ddot p = 0$ everywhere, so the cost is 0, its smallest possible value. Bends and speed changes both require acceleration.

Sampling-based planning: EST, RRT, RRT*

10/15 · 10/21
Big ideaDon't map the free space. Just throw random samples, keep the ones you can reach, and grow a tree from the start until it touches the goal. RRT grows fast by always extending the nearest node toward a random point. RRT* also rewires the tree so paths straighten out over time.
Four ingredients
  • Collision check: is configuration $q$ in free space?
  • Sampler: random configurations (uniform by default; fine if they land in obstacles).
  • Local planner: can two samples be connected simply? Default: straight line + collision checks along it.
  • Distance: Euclidean by default; used for "nearest" and "close to goal."
The algorithms

Run RRT*: watch the cost drop as it keeps sampling. Then push the radius to 2.0 (the activity's value): the gaps shrink to ~0.2 wide and the tree struggles. That's the narrow passage problem.

Narrow passages and other tricks
  • A tiny gap = tiny probability that a sample lands in it. Fixes: sample more; bias samples toward obstacle edges using rejected samples (usually not worth it); better local planner (curves instead of straight lines, but expensive).
  • Shortcutting post-process: try to connect non-adjacent path nodes directly; straighter, fewer nodes. This is what OMPL's simplifySolution() does.
  • Kinodynamic planning: plan trajectories (position + time), not just paths. Pick a tree node, sample random inputs (e.g. $v, \omega$ for a car), integrate forward. Every branch is dynamically feasible by construction; a good steering function helps.
Why does RRT explore faster than EST?
Uniform random points mostly land in big unexplored regions, and the nearest tree node to them is on the tree's frontier. So the tree is pulled outward (Voronoi bias), instead of piling up near the root.
What does RRT* rewiring do to a neighbor $x_{neigh}$?
If cost(root→$x_{steer}$) + dist($x_{steer}$, $x_{neigh}$) < current cost of $x_{neigh}$, and the edge is collision-free, make $x_{steer}$ its parent. Branches straighten toward the root.

The dynamic robot: equations of motion

Kinematics says where things are. Dynamics says how forces make them move: a model $\dot x = f(x,u)$ with state $x = [q;\ \dot q]$. Notes so far cover 10/26; later lectures (Lyapunov, LQR, MPC) get added as they happen.

Equations of motion, Newton's method, the mass matrix

10/26
Big ideaTo control a robot you need an ODE for it. Newton's way tracks every force, including the reaction forces holding joints together. Lagrange's way works directly in joint coordinates, so those constraint forces never show up. Both start from kinetic energy, and for a robot KE is a quadratic in $\dot q$ whose matrix is the mass matrix $M(q)$.
$$\dot x = f(x,u),\qquad x = \begin{bmatrix}q\\ \dot q\end{bmatrix}\ \ (\text{generalized coordinates and velocities}),\ \ u = \text{actuator inputs}$$
equations of motion (EoM)
Newton
  • $F = ma \Rightarrow \ddot x = F/m$. Easy for a free body, messy with joints: you must add reaction forces that enforce each kinematic constraint.
  • For serial robots there's a fast recursive version (Featherstone): (1) tip → root: accumulate forces/torques; (2) root → tip: propagate accelerations. It works in workspace coordinates (6N numbers for N links).
  • Tron's analogy: reaction forces balancing applied forces ≈ constraint gradients balancing the cost gradient at a constrained minimum ($\nabla f = \lambda\nabla g$).
Kinetic energy and the mass matrix
$$KE = \tfrac12 m\|\dot p\|^2 = \tfrac12 m\|J_p(q)\dot q\|^2 = \tfrac12\dot q^T\underbrace{\big(mJ_p(q)^TJ_p(q)\big)}_{M(q)}\dot q$$
for a point mass at p(q). For several masses, sum the M's. M is symmetric positive (semi)definite

This is where topic 2 pays off: the Jacobian turns joint speeds into Cartesian speeds, and KE is just ½m(speed)².

Example: pendulumPoint mass at distance $\ell$, angle $q$: $p = \ell[-\sin q,\ \cos q,\ 0]^T$, so $J_p = \ell[-\cos q,\ -\sin q,\ 0]^T$ and $$M = m\ell^2(\cos^2 q + \sin^2 q) = m\ell^2,\qquad KE = \tfrac12 m\ell^2\dot q^2.$$ Constant mass matrix, because the mass is always the same distance from the pivot.
10/26 poll: is $\dot q = J^{-1}\dot p$ correct?
Only if $J$ is square and invertible. The always-true statement is $\dot p = J\dot q$ with $J = \partial p/\partial q$.
For a 2-link planar arm with point masses at each tip, how would you build $M(q)$?
$M = m_1J_1^TJ_1 + m_2J_2^TJ_2$, where $J_i$ is the 2×2 position Jacobian of mass $i$ w.r.t. $(q_1,q_2)$ ($J_1$ has a zero second column). Unlike the pendulum, $M$ depends on $q_2$.

Hamilton's principle, Euler-Lagrange, d'Alembert

10/26
Big ideaOf all the ways the robot could get from configuration A to configuration B, nature picks the one where a certain integral (the action) is stationary: wiggle the path slightly and the action doesn't change to first order. That's "grad = 0," but for whole trajectories. Setting this variation to zero produces the equations of motion.
$$\mathcal A = \int_a^b L(q,\dot q)\,dt,\qquad \delta\mathcal A = \frac{\partial}{\partial s}\mathcal A\big(\vartheta(\cdot,s)\big)\Big|_{s=0} = 0$$
Hamilton's principle with L = KE (no external forces). A variation ϑ(t,s) equals q(t) at s = 0 and keeps both endpoints fixed for all s

Analogy: ordinary optimization perturbs a point $x$ and asks for zero change. Here we perturb a whole curve $q(t)$ (keeping its ends pinned) and ask the same thing. It's a law (it fits experiments); usually the true path is a minimum, but not always.

Derivation sketch
  1. Differentiate under the integral: $\delta\mathcal A = \int\big(\frac{\partial KE}{\partial q}\delta q + \frac{\partial KE}{\partial\dot q}\delta\dot q\big)dt$.
  2. Integrate the second term by parts. The boundary term vanishes because variations pin the endpoints.
  3. Left with $\int\big[\frac{\partial KE}{\partial q} - \frac{d}{dt}\frac{\partial KE}{\partial\dot q}\big]\delta q\,dt = 0$ for every $\delta q$, so the bracket itself must be zero.
$$\frac{d}{dt}\Big(\frac{\partial KE}{\partial\dot q}\Big) - \frac{\partial KE}{\partial q} = 0\qquad\text{(Euler-Lagrange)}$$ $$\text{with } KE = \tfrac12\dot q^TM(q)\dot q:\qquad M(q)\ddot q + \dot M(q)\dot q - \tfrac12\begin{bmatrix}\dot q^T\frac{\partial M}{\partial q_1}\dot q\\ \vdots\\ \dot q^T\frac{\partial M}{\partial q_N}\dot q\end{bmatrix} = 0\ \ \Longleftrightarrow\ \ M(q)\ddot q + \Gamma(q)(\dot q,\dot q) = 0$$
∂KE/∂q̇ = M q̇, d/dt(M q̇) = Ṁq̇ + Mq̈. Γ = Christoffel symbols: velocity-squared terms (centrifugal/Coriolis)
Heads up: in the 10/26 notes the ½[…] term is written with a + sign. Moving $\frac{\partial KE}{\partial q} = +\tfrac12[\dot q^T\partial_{q_i}M\dot q]_i$ to the other side makes it −. Intuition from Tron: "$ma = 0$" plus a correction $\Gamma$ that comes from the constraints.
Pendulum, no forces (from the notes)$M = m\ell^2$ constant, so $\partial M/\partial q = 0$ and $\dot M = 0$. Euler-Lagrange: $m\ell^2\ddot q = 0 \Rightarrow \ddot q = 0$. Constant angular velocity: with no gravity, it just spins.
Adding forces: virtual work and d'Alembert-Lagrange
  • Power $P = \langle F, \dot p\rangle$, work $W = \int P\,dt$. Virtual work: $\delta W = F^T\delta p$, the work a force would do along a variation.
  • d'Alembert-Lagrange: Hamilton's principle balanced with virtual work, $\delta\mathcal A_{KE} = \int\delta W\,dt$ (where the 10/26 notes stop).
Where this leads (standard result, beyond the 10/26 notes)Since $\delta p = J_p\delta q$, virtual work is $\delta W = (J_p^TF)^T\delta q$. The force shows up in joint space as $\tau = J_p^TF$, and the equation becomes $$\frac{d}{dt}\frac{\partial KE}{\partial\dot q} - \frac{\partial KE}{\partial q} = J_p^TF.$$ Hanging pendulum ($p = \ell[\sin q, -\cos q, 0]^T$, gravity $F = [0,-mg,0]^T$): $J_p^TF = -mg\ell\sin q$, so $m\ell^2\ddot q = -mg\ell\sin q \Rightarrow \ddot q = -\tfrac g\ell\sin q$. The familiar pendulum. (Same $J^T$ that maps errors to joint steps in IK, now mapping forces to torques.)
Why does the boundary term from integration by parts vanish?
It's evaluated at $t=a$ and $t=b$, multiplied by $\partial q/\partial s$ there. Variations keep the endpoints fixed, so $\partial q/\partial s = 0$ at both ends.
Why can Lagrangian mechanics ignore joint reaction forces?
Generalized coordinates only describe motions the joints allow. Reaction forces are perpendicular to every allowed motion, so they do zero virtual work and drop out.
